# 跃动童年 · 城市少儿体适能课程分组与伤情记录系统

## 原始需求

> 设计城市少儿体适能课程分组与伤情记录页面，可使用 React、TypeScript 和 Zustand。教练为孩子建立档案，录入年龄、身高体重、基础体测、运动史、过敏、既往伤病和家长期望。系统根据平衡、敏捷、力量、柔韧、协调和注意力为孩子推荐班级。上课前，前台核验签到、装备、身体状态和家长授权；上课中，教练记录热身、跳跃、爬行、投掷、平衡木和团队游戏表现。若孩子恐惧器械、动作代偿、摔倒擦伤、与同伴冲突或家长临时要求升阶，页面要让教练、前台、店长和家长围绕同一节课处理。课后，家长看到训练表现、注意事项、家庭练习和是否适合升阶。伤情记录、请假补课、升阶评估和课包消耗会进入同一学生档案，帮助门店解释课程安排和安全责任。页面还要支持店长按班级、教练和动作项目复盘伤情，判断某些训练设计是否需要降级、换器械或增加助教。家长复购前会看到训练风险和成长建议。页面还要把孩子能力、课次表现、伤情和家长沟通形成连续成长记录，门店处理升阶、退费或安全争议时能回到具体动作和课堂证据。

## 技术栈

- **前端**：React 18 + TypeScript + Vite
- **状态管理**：Zustand（persist 持久化到 localStorage，刷新不丢数据）
- **图表**：Recharts（六维能力雷达图、伤情分布柱状图）
- **路由**：React Router v6
- **部署**：多阶段 Dockerfile（node 构建 → nginx-unprivileged 运行，非 root 用户 + HEALTHCHECK）

## 一键启动（Docker）

```bash
cp .env.example .env   # 可选，默认端口 3001
docker compose up -d --build
```

启动后访问 `http://localhost:<CC_PUBLISH_PORT>`（默认 `http://localhost:3001`）。

- 容器内部端口固定 **8080**，仅应用端口发布到宿主（`${CC_PUBLISH_PORT}:8080`）。
- 本系统为纯前端应用（数据存于浏览器 localStorage），无数据库等依赖服务，因此 compose 仅含 app 一个服务。
- 验证方式 = 宿主 `docker compose up -d` 后，用 `docker compose port app 8080` 取映射端口访问；验证完 `docker compose down` 释放资源。

## 本地开发

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # tsc 类型检查 + vite 构建
npm run verify   # 验收脚本：调班负荷不丢拦截 + 日期边界 + 伤情分级回访全流程
```

> **本周训练负荷计算规则**：严格限定在同一自然周 `[本周一, 本周日]`，按「课次名册中是否包含该孩子」过滤（与当前班级无关）。调班时系统自动同步名册——加入新班未开课课次、旧班未开课课次仅移除空白名册（已有签到/拦截/请假/评分记录的保留为本周事实）。因此调班后：旧班本周已出勤与被拦截的课次仍计入负荷，新班本周后续课次继续累计；**下周及以后的未来排课（如 2026-09-21 所在周）即使名册已同步，也不会提前稀释本周 planned/percent**。教练档案与家长端共用同一计算函数，结果一致。`npm run verify` 复现「A 班拦截 → 调班 B 班 + 下周课次边界」场景做 18 项断言。

## 功能地图（按角色）

### 教练（coach）
- **建档测评**（`/students/new`）：录入年龄、身高体重、运动史、过敏、既往伤病、家长期望 + 六项体测滑杆（平衡/敏捷/力量/柔韧/协调/注意力），系统综合**体测均分 + 年龄 + 既往伤情 + 家长目标**实时推荐班级，保存即建档 + 分班 + 生成家长账号。
- **课次管理**（`/sessions/:id`）：课中为每个学员对热身、跳跃、爬行、投掷、平衡木、团队游戏六项打分（优秀/良好/需关注），一键登记恐惧器械、动作代偿、摔倒擦伤、同伴冲突、家长升阶要求五类事件；被拦截/请假学员的**未上课原因**在课中记录页直接可见；课后填写注意事项、家庭练习、是否适合升阶，「完成课次」自动消课并推送报告。
- **伤情分级记录**：登记「摔倒擦伤」时展开完整表单——伤情分级（轻微/较重）、具体动作、场地、护具佩戴、伤情照片、动作视频、现场处理、复课建议、下节课需避开的动作；较重伤可附加暂停训练天数，系统按需避开动作自动推导**低风险替代动作**。记录提交后**家长确认才进入训练计划**。
- **伤情提醒**：课中记录页顶部对本节课在册学员显示生效中的伤情提醒（避开哪些动作、暂停至哪天、替代动作是什么）。
- **调班留痕**：学员档案页「调整班级」必须填写原因，与系统推荐记录一起进入分班/调班历史。

### 前台（front）
- **课前核验**：对每节课每个学员核验签到、装备、身体状态、家长授权四项（全部通过或登记请假后教练才能开课），支持核验备注（如"昨晚咳嗽，观察中"）。
- **课前拦截**：孩子到店出现咳嗽、疲劳或腿部疼痛时可发起拦截，系统按**课包规则（体验包 1 次/月、成长包 2 次/月、学年包 3 次/月免费额度）+ 医生证明 + 历史请假**实时预判是否返还课时；拦截后教练在课次页看到未上课原因，家长端看到课时处理结果并可确认知晓。
- **事件协同**：事件登记后「已联系家长」一键流转为待家长确认；学员档案页可登记请假（不消课）与补课。

### 店长（manager）
- **伤情复盘**（`/review`）：按班级、教练、动作项目筛选伤情/代偿/恐惧事件，查看项目分布柱状图与明细表，输出训练设计调整结论（保持/降级/换器械/增加助教）并留痕。
- **伤情回访**：较重伤在家长确认后进入「待回访」，店长填写回访记录（恢复情况、复课安排）后转入回访中，恢复良好可闭环；工作台有待办汇总。
- **事件闭环**：对每起事件做设计处置与复核闭环；处理家长临时升阶要求（通过则自动调班，暂缓则记录原因），**升阶评估弹窗与成长时间线均引用伤情记录**。

### 家长（parent）
- **我的孩子**（`/parent`）：六维能力雷达（含与上次对比）、课后报告（训练表现/注意事项/家庭练习/升阶建议，需确认已读）、待确认事件一键知晓闭环。
- **伤情记录与回访**：查看伤情分级记录（动作、场地、护具、照片/视频、现场处理、复课建议、暂停训练建议与替代动作），**确认后才进入后续训练计划**。
- **课时处理结果**：课前拦截的症状、说明与课时返还/不返还结果（含判定依据），家长确认知晓。
- **本周训练负荷**：出勤/计划课次与负荷百分比，拦截导致的负荷下降有明确提示与恢复建议。
- **复购参考**：课包余量 + 「训练风险与成长建议」面板（既往伤病、课堂伤情处置、薄弱维度、家庭练习），复购前充分知情。

### 同一学生档案（`/students/:id`）
基础档案、体测历史与雷达、**系统推荐班级（综合六项体测 + 既往伤情 + 家长目标，调班必须填写原因并留痕，分班/调班历史可回溯）**、课包消耗进度、**本周训练负荷**、伤情分级记录（含回访状态）、课前拦截记录、**连续成长时间线**（建档/体测/分班/课次表现/伤情事件/伤情回访/课前拦截/请假/补课/升阶评估/课包消耗/家长沟通）——处理升阶、退费或安全争议时可回到具体动作项目和课堂证据。

## 一节课的完整动线（演示脚本）

1. 前台 `front` 登录 → 课次管理 → 进入今日「启蒙 A 班 10:00」→ 为吴天天完成四项核验（孙甜甜有身体状态备注）→ 全部通过后教练才可开课。
2. **课前拦截演示**：前台对到店学员点击「🚫 课前拦截」→ 勾选咳嗽/疲劳/腿部疼痛 → 系统实时预判课时处理（吴天天的体验包本月已请假 1 次，免费额度用尽 → 无医生证明时判定「不返还」；勾选「有医生证明」则判定「返还」）→ 确认后教练在课中记录页看到未上课原因，家长端（如 `parent6`）看到课时处理结果并确认知晓；该生本周训练负荷随之下降（学员档案页可见）。
3. 教练 `coach` 登录 → 同一节课「开始上课」→ 课中记录六项评分 → 给学员登记「恐惧器械 · 平衡木」等事件。
4. 前台在事件中心点击「已联系家长」→ 状态变为待家长确认。
5. 家长 `parent3`（孙丽）登录 → 确认事件闭环；查看课后报告并确认已读；孙甜甜本周二的拦截记录与课时返还结果也在「课时处理结果」中。
6. 店长 `manager` 登录 → 伤情复盘看到平衡木事件分布 → 新增「启蒙 A 班 · 平衡木 · 降级」调整结论 → 在学员档案时间线中可回看全部证据链。
7. 店长处理郑好妈妈的「家长临时升阶要求」（事件中心，open 状态）→ 通过升阶 → 郑好自动调入进阶 C 班并记录升阶评估（弹窗与时间线均引用伤情记录）。
8. **调班留痕演示**：教练在任一学员档案点「调整班级」→ 选择目标班级并填写原因（参考系统推荐的体测/伤情/家长目标分析）→ 分班/调班历史永久留痕。
9. **伤情分级回访演示**：家长 `parent8`（何军）登录 → 「伤情记录与回访」中确认何沐阳的较重伤记录（跳跃·左踝，暂停 7 天，替代动作：投掷、热身）→ 店长 `manager` 在伤情复盘页发起回访并闭环；教练在进阶 C 班课次的课中记录页可看到「避开跳跃、平衡木」的伤情提醒。

## 目录结构

```
├── Dockerfile              # 多阶段：node 构建 → nginx-unprivileged 运行（非 root + HEALTHCHECK）
├── docker-compose.yml      # 仅 app 服务，${CC_PUBLISH_PORT}:8080
├── nginx.conf              # SPA 路由回退 + 静态资源缓存
├── .env.example            # CC_PUBLISH_PORT / COMPOSE_PROJECT_NAME
└── src/
    ├── types.ts            # 全部领域模型（学员/班级/课次/事件/拦截/时间线/体测…）
    ├── data/seed.ts        # 演示数据（8 学员、3 班级、6 事件、1 拦截、完整时间线）
    ├── store/useStore.ts   # Zustand store：建档/核验/拦截/记录/事件/伤情回访/消课/升阶等全部 action
    ├── utils/recommend.ts  # 班级推荐（体测+伤情+家长目标）、课时返还评估、本周训练负荷、替代动作推导
    ├── components/         # 布局、雷达图、事件卡片、伤情记录卡、滑杆等
    └── pages/              # 登录/工作台/学员/建档/课次/事件中心/复盘/家长端
```
